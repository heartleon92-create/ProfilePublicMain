What Is It?

Your own website — at your own address.

A Personal Profile Website is a dedicated website that represents you online. It belongs to you and can be shared using a public URL.

A profile website can include:

Personal introduction Profile photo Career information Education Skills Experience Portfolio Projects Services Certificates Social links Contact information Resume / CV Custom sections

Your URL

Depending on deployment, your profile will be reachable at a URL such as:

yourname.example.com  —  custom domain (optional, purchased separately)

profilecraft.github.io/yourname  —  free static hosting URL

A custom domain is not included unless purchased and configured as part of your project.

Who Is It For?

For anyone who needs a professional presence online.

Note: Profile Craft does not provide medical, legal or other regulated professional services. The profile website is only the platform that presents your professional information.

Three Profile Types

More than a static page. Choose the level you need.

Profile Basic

A clean, static profile

A professional one-page profile built with HTML, CSS and JavaScript. Ideal for students, job seekers and professionals who need a simple online presence.

  • Static HTML / CSS / JavaScript
  • Deployable to free static hosting
  • Updates handled as project revisions
Profile Dynamic

Content managed from data

Everything in Basic, plus content stored in structured data (JSON / API / Cloudflare-based). Sections render dynamically, so content updates are easier and more flexible.

  • JSON-based profile data
  • Dynamic portfolio, skills and experience
  • More advanced JavaScript interactions
Profile Functional

Profile as a small web application

Advanced functionality on top of Dynamic — appointment/request forms, schedule display, service selection, filtering, custom calculators and interactive components.

  • Interactive portfolio and filters
  • Appointment / request interface
  • Custom frontend logic

What "Dynamic" does not mean

Dynamic content does not automatically mean a backend, admin panel, user accounts, authentication or a database. If you need login, an admin dashboard, or server-side data management, that becomes a custom / backend project — quoted separately.

Sections vs pages vs functions

Profile sections such as About, Skills, Experience, Education, Portfolio and Contact can all exist on one profile page — they are not separate pages. A separate URL such as /projects or /portfolio/project-name may count as a separate page depending on the project structure. A complex interactive feature — appointment system, admin dashboard, database, authentication, booking, API integration — is not a "page"; it is scoped by functionality and complexity.

Three Architectures

How each profile type is built.

Static

Static Profile

Plain HTML, CSS and JavaScript. Content lives in the HTML or in a small amount of JSON.

  • HTML + CSS + JavaScript
  • GitHub Pages / Cloudflare Pages / static hosting
  • Low cost, fast, no backend
  • Best for basic professional profiles
Dynamic

Dynamic Profile

HTML, CSS and JavaScript with structured data (JSON / API / Cloudflare-based) driving the content rendering.

  • Easier content management architecture
  • Dynamic rendering of sections
  • More flexible data structure
  • Cloudflare services may have usage limits or paid components
Functional

Functional Profile

Closer to a small web application. May use Cloudflare Workers, D1, APIs, a backend or a database depending on the project.

  • HTML + CSS + JavaScript
  • Cloudflare Workers / D1 (where appropriate)
  • API / backend / database depending on project
  • Each advanced function is scoped separately
Deployment Options

Three deployment paths, from free to professional.

A static profile can be deployed for free. A professional profile with a custom .com domain and paid hosting is also available. Both are valid choices — it depends on your budget and how established your professional brand needs to look.

A

Free / Budget Deployment

For static profiles where recurring cost should be as low as possible.

Platforms

  • GitHub Pages
  • Cloudflare Pages
  • Other suitable static hosting

Notes

  • Suitable for Basic and simple Dynamic profiles
  • A free platform URL can be used without a .com domain
  • Backend or database requirements may need a different deployment
Hosting: Potentially 0 MMK / month Qualifying static deployments only. Domain, backend services, databases and APIs are separate.
B

Professional — .com + Paid Hosting

For profiles that need a branded address or a backend.

Setup

  • .com domain (purchased separately)
  • DNS and SSL configuration
  • Paid hosting and deployment
  • For profiles requiring server-side / backend / database

Notes

  • Domain and hosting are paid to third-party providers — not to Profile Craft
  • Recurring annual cost — separate from the development fee
  • Suitable for all three packages
Suggested annual infrastructure budget: ≈ 140,000 – 380,000+ MMK / year Planning range only (domain + paid hosting). Actual costs depend on registrar, provider, renewals and requirements.
C

Cloudflare-Native Architecture

For dynamic or functional profiles using Cloudflare's full stack.

What Cloudflare provides

  • DNS, CDN and SSL
  • Security and firewall
  • Cloudflare Pages for static hosting
  • Workers for serverless functions
  • D1 for lightweight database storage

Notes

  • Cloudflare Pages alone is not a PHP/MySQL server
  • If you need PHP + MySQL, use PHP-compatible hosting
  • Free tier limits apply; Workers and D1 have usage-based limits
  • Not every Cloudflare feature is permanently free
Cost depends on the architecture: Free tier for simple use · usage-based for advanced
Architecture Options

Two technical directions. Only one is used at a time.

These are alternative approaches, not combined features. Static + JSON is the default for Basic and Dynamic. Cloudflare-native is a separate approach used only for Functional profiles that need it.

A · Static + JSON

Default for Profile Basic and Profile Dynamic.

Visitor
↓
Static frontend (HTML · CSS · JavaScript)
↓
JSON data files
↓
Cloudflare Pages / GitHub Pages

No backend, no database. Content updates are made by editing the JSON data files.

B · Cloudflare-Native

Used only for Functional profiles that need serverless functions or a database.

Visitor
↓
Cloudflare (DNS · SSL · CDN · Security)
↓
Cloudflare Pages (frontend)
↓
Cloudflare Workers (functions / API)
↓
Cloudflare D1 (database)

Cloudflare Pages is not a PHP/MySQL server. For PHP + MySQL profiles, use PHP-compatible hosting instead.

Cost Structure

Development, domain and hosting are three separate things.

Development is a one-time fee paid to Profile Craft. Domain and hosting are recurring costs paid to third-party providers. They are never bundled into one number.

Paid to third-party domain and hosting providers — not to Profile Craft.
