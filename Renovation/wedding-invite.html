Feature D · Key differentiator

QR Invitation & Guest Check-in

This is the feature that turns an invitation into an event tool. Each guest or invitation group receives a unique code. At the door, authorised staff scan and validate it — so entry can be confirmed and duplicate entry can be detected.

How check-in works

  1. Guest list supplied

    The couple or an authorised organiser provides the guest list.

  2. Unique codes generated

    The system generates a unique invitation code or QR code for each eligible guest or invitation group.

  3. Guest presents the code

    Guests present their invitation QR code at the event entrance.

  4. Staff scans the code

    An authorised staff member scans the code using a compatible device.

  5. Invitation validated

    The check-in screen validates the invitation and shows the relevant guest or invitation status.

  6. Status recorded

    Once checked in, the status is recorded so accidental duplicate entry can be detected.

Feature F

Guest Information & RSVP Optional

Optional guest-response functionality, available depending on the package you choose and the implementation required. RSVP is a planning tool — it is not the same thing as event check-in.

  • RSVP form
  • Attendance confirmation
  • Number of attending guests
  • Dietary or other event-related notes, if required
  • Organiser view of RSVP responses
Important distinction: An RSVP response is not a check-in. A guest confirming online does not mean the guest has arrived at the event. If RSVP data is stored, it is protected with access restrictions and handled as personal information.
Backend note: A collecting RSVP form needs somewhere to store responses. This may require a backend or a managed data service, and is not part of every package.

How the service works

From wedding details to launch

A clear, six-step process. Projects that include QR validation, RSVP or guest-list management are given extra time for backend work, security checks and real-device testing.

  1. Share your wedding details

    The couple provides names, event information, photos and venue details.

  2. Choose your features

    Confirm the invitation design, gallery, map, RSVP or QR check-in functions you need.

  3. Design & development

    Profile Craft builds the agreed website and features.

  4. Review & testing

    The couple checks the content, links, mobile layout and agreed interactive functions.

  5. Payment & approval

    Payments follow the quotation and the agreed milestone terms. The schedule is confirmed in writing before work begins.

  6. Launch & share

    Publish the website and share the invitation link or QR codes according to the agreed delivery plan.

Technical scope & limitations

Not every feature needs the same kind of build

We would rather be clear about this up front. Some features can live on a static website; others need a backend or a managed data service.

Possible with a static website

No server or database required for these to work.

  • A simple digital invitation page
  • Static photo gallery with a lightbox
  • Venue details, map link and directions button
  • Wedding schedule and event information
  • Shareable invitation link and display of a QR graphic

Needs a backend or managed data service

These involve storing data or checking it against records, so extra work and testing are required.

  • QR code validation (not just QR code display)
  • Unique invitation identifiers tied to a guest list
  • Persistent check-in records and duplicate detection
  • RSVP forms that store and display responses
  • Guest-list administration and attendance summaries
  • i QR generation ≠ QR validation. A scanner interface on its own does not guarantee that an invitation is valid.
  • i Hosting is chosen to match the features. A static host alone cannot provide a PHP backend or a persistent database. We select an implementation that suits the agreed feature set rather than the other way around.
  • i Third-party costs are separate. Domain registration, hosting, database services, file storage and other third-party service charges are explained separately where they apply. Profile Craft can assist with setup where agreed, but does not act as a domain registrar and does not provide unlimited infrastructure.
  • i Not every feature is in every package. Optional functions and backend-dependent features are confirmed in your quotation before development begins.
