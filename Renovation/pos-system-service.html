What "module" means here

In a POS system, a "page" is not the same as a marketing website page. One module can contain several screens. For example: Products is one module, and it contains a Product List, Add Product, Edit Product and Product Details view — those are related screens inside a single module. Package screen counts are therefore an approximate scope indicator, not an unlimited-page guarantee. Additional modules beyond the package scope are quoted separately.

Data & Scale

The right architecture depends on your data size.

We plan the database structure, backups and server resources according to how much data your business actually produces.

Small business

Suitable for relatively small data volume — a single shop or small restaurant with modest daily transactions.

Growing business

Requires a more structured database, indexing, a proper backup strategy and adequate server resources.

Larger / multi-branch

Requires more advanced architecture, infrastructure planning and dedicated server resources.

We do not quote a fixed maximum number of records unless it has been tested against your actual system and infrastructure.

What Cloudflare actually does

Cloudflare provides DNS, SSL, CDN, security, static frontend hosting, edge services, Workers and D1 where suitable. It is not accurate to describe Cloudflare as a free PHP host. Cloudflare Pages static assets are currently free/unlimited; Functions use Workers quotas and pricing; D1 has its own usage-based limits. The final infrastructure cost depends on which architecture is used and how much it is used.

FAQ

Common questions about POS systems.

Is a POS the same as a business website?

No. They are different products for different audiences. A business website is customer-facing — customers see your business online. A POS is internal — you and your staff use it to run sales, orders, inventory and reports. Some businesses need both, but they are quoted and built as separate projects.

How do you count "modules" for pricing?

A module is a functional area of the system, not a single screen. For example, Products is one module — even though it contains a product list, add product, edit product and product details screens. Package screen counts are approximate scope indicators, not unlimited-page guarantees.

Can Cloudflare host my PHP POS system?

No. Cloudflare Pages hosts static frontend files — it does not run PHP. For a PHP + MySQL POS, you need PHP-compatible hosting with a MySQL database. Cloudflare can still be used for DNS, SSL, CDN and security in front of that hosting. If you want a Cloudflare-native architecture instead, that is a separate approach using Cloudflare Workers and D1, and it is quoted separately.

Does Profile Craft provide the domain and hosting?

No. Profile Craft is not a domain registrar or hosting provider. We help you select, purchase, configure and deploy using suitable third-party services as part of the project. Domain and hosting are paid to those third-party providers — not to Profile Craft — and they are separate recurring costs.

Are the displayed prices final?

No. Every price shown is a reference starting price. The final development fee depends on the number of modules, UI and backend complexity, database structure, user roles, reports, integrations and data migration. Infrastructure cost depends on the provider and plan you choose. All prices are confirmed in a written quotation after we agree on the requirements.

Can you build a fully custom system?

Yes, if the required functions and technical scope are suitable. We will discuss the modules, data structure, users and infrastructure needed before quoting. For larger systems — multi-branch, higher concurrency, or integrations with external services — the project is scoped and quoted separately.

Need a different POS system?

Every business operates differently. If the standard packages do not match your workflow, Profile Craft can define a custom system scope based on your actual operations.
